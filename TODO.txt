I added storage:clean-orphans and scheduled it to run daily. I ran the report only, on the central storage, and it removed nothing.

Orphan command: it finds files on the public disk that no database row or column references, in the central storage and in each tenant's. It leaves alone files modified in the last 48 hours (in-flight uploads), dotfiles and livewire-tmp.
Central result: it found 12,219 orphan files, about 2.2 GB, mostly under products/ and productvariants/. I spot-checked three of the products/ ones. Two belong to a product that still exists, and one to a product that no longer exists. None has a files row.
Schedule: both commands now run daily in bootstrap/app.php, and schedule:list shows them:
02:00: images:convert-avif, which converts any image saved in a non-AVIF format.
03:00: storage:clean-orphans --delete.
Reversible by default: --delete moves orphans to storage/app/orphan-trash/<timestamp>/… instead of unlinking them. You can restore from there, and --purge is the only option that deletes permanently. Empty that folder yourself once you've checked the site.
Scheduler: the schedule only runs if your server runs php artisan schedule:run every minute from cron.
Order: run the real images:convert-avif once before the first 03:00 cleanup, with a backup first. The cleanup treats a file as in use only if a database row mentions its current path, so anything left unconverted is still safe.
Hard-coded paths: a file that only code or a blade view refers to by a fixed path, with no database row, would be treated as an orphan. Preview the first run with php artisan storage:clean-orphans and check the folder list. Exclude any folder like that with --exclude=dir in the scheduled call.
