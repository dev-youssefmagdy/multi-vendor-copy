OpenAI-based translation workflow for this project
Last updated: 2026-04-19

Purpose
-------
This document describes how to integrate OpenAI for automated translation tasks in this multi-vendor Laravel project, where translation assets live in the repository (examples: resources/lang/ and a top-level lang/ directory with JSON and per-locale folders).

Scope
-----
- Which files: resources/lang/*, resources/lang/{locale}/*.php, resources/lang/{locale}.json, and any project-specific JSON translation files found at the repo root (e.g. lang/en.json, lang/ar.json).
- Goal: create a safe, reviewable pipeline that auto-generates draft translations using the OpenAI API, preserves placeholders, and writes results back to the repo for human review.

High-level flow
---------------
1) Extract source strings
   - Scan translation files (JSON + PHP array files) and source code for usage of __(), trans(), and @lang to build a list of keys and source texts.
   - Prefer extracting by key when available; otherwise extract raw strings with file+line context.

2) Normalize and batch
   - Build batches of key->text mappings (e.g. JSON object) to translate.
   - Keep batches small enough to avoid token limits; recommended batch sizes: 100–300 short strings or ~2k–4k tokens per request (adjust to the model you use).

3) Prompt and send to OpenAI
   - Use the Chat Completions API (or new Chat endpoint) and a chat-capable model.
   - Use a strict prompt template that instructs the model to return only JSON mapping original keys to translated strings and to preserve placeholders and HTML.

Prompt template (example)
-------------------------
System message:
You are a professional translator that outputs valid JSON only. Do not include any explanation or extra text.

User message (example):
Translate the following JSON values from English to Arabic. Preserve placeholders exactly (examples: :name, {count}, %s), preserve any HTML tags, and do not change keys. Return only a single JSON object mapping the same keys to translated strings.

Input JSON:
{"welcome":"Welcome, :name!","items":"You have {count} items."}

Expected output (only JSON):
{"welcome":"مرحبا، :name!","items":"لديك {count} عناصر."}

Important instructions for the prompt
- Tell the model to return valid JSON only (no markdown, no commentary).
- Explicitly instruct to preserve placeholders exactly.
- Ask for consistent punctuation and whitespace.
- If the model cannot translate a string (ambiguous), return the original value or a flagged placeholder value (e.g. "__REVIEW__:<original>").

Model settings
--------------
- `temperature`: 0.0 for deterministic output.
- `max_tokens`: choose enough to cover the expected response; set conservatively and chunk when needed.
- Model: choose a chat-capable model available on your account (example placeholders: gpt-4o-mini or equivalent). Use smaller/cheaper models for large runs and a higher-quality model for final review.

Example cURL (chat completions)
--------------------------------
curl https://api.openai.com/v1/chat/completions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model":"gpt-4o-mini",
    "messages":[
      {"role":"system","content":"You are a JSON-only translator. Return only a JSON object."},
      {"role":"user","content":"Translate the following JSON from English to ARABIC. Preserve :name and {count}: {\"greeting\":\"Hello, :name!\"}"}
    ],
    "temperature":0
  }'

PHP (Guzzle) example
---------------------
// composer require guzzlehttp/guzzle
$client = new \GuzzleHttp\Client();
$payload = ["greeting" => "Hello, :name!"]; // JSON payload sent as string in the prompt
$response = $client->post('https://api.openai.com/v1/chat/completions', [
  'headers' => [
    'Authorization' => 'Bearer ' . env('OPENAI_API_KEY'),
    'Content-Type' => 'application/json',
  ],
  'json' => [
    'model' => 'gpt-4o-mini',
    'messages' => [
      ['role' => 'system', 'content' => 'You are a JSON-only translator. Return only a JSON object. Preserve placeholders.'],
      ['role' => 'user', 'content' => "Translate the following JSON from English to ARABIC. Preserve placeholders: " . json_encode($payload)]
    ],
    'temperature' => 0
  ]
]);
$body = json_decode((string)$response->getBody(), true);
$text = trim($body['choices'][0]['message']['content'] ?? '');
$translations = json_decode($text, true);
if (json_last_error() !== JSON_ERROR_NONE) {
  // Handle parse errors: log for manual review and fallback behavior
}

Post-processing and validation
-----------------------------
- Parse the returned JSON and verify every requested key is present.
- Verify placeholders are preserved exactly; compare source vs translation tokens.
- If keys are missing or invalid JSON is returned, retry the request (with a smaller batch) or tag results for manual review.
- Always keep a backup of the original translation files before writing.

Writing translations back
-------------------------
- For JSON translation files: write with json_encode($translations, JSON_UNESCAPED_UNICODE | JSON_PRETTY_PRINT).
- For PHP array files: convert the response into the proper PHP array format and write atomically.
- Commit translation changes on a branch and open a PR for linguistic review.

Edge cases
----------
- ICU/pluralization: do not let the model rewrite the ICU structure. If messages contain ICU syntax, include explicit instructions to keep the ICU syntax unchanged and translate only the translatable segments.
- HTML/Markdown inside strings: instruct the model not to alter tags.
- Variables and placeholders: enforce exact preservation (case-sensitive).

Operational notes
-----------------
- Rate limits & retries: implement exponential backoff for 429/5xx responses.
- Caching: avoid re-translating unchanged strings; store a translation memory (hash of source text → translation) to save cost.
- Queueing: run translation jobs asynchronously (Laravel Jobs/Queue) to avoid blocking web requests.
- Security: keep OPENAI_API_KEY in .env and never commit it.

Quality assurance
-----------------
- Create a script to compare key sets between source locale and target locale; flag missing or extra keys.
- Run spot checks by native speakers or integrate with a translator review flow (PR review with language owners).

Suggested implementation components for this repo
-----------------------------------------------
1. An Artisan command php artisan translations:translate {locale} --source=en that:
   - Extracts keys or loads a source locale JSON
   - Batches requests to OpenAI using the prompt template above
   - Validates and writes results to resources/lang/{locale}.json or resources/lang/{locale}/ files
   - Commits changes to a feature branch and opens a PR (optional automation)

2. A background job to process large translation runs with retry/backoff.

3. A small test that asserts parity of keys across locales (CI job).
