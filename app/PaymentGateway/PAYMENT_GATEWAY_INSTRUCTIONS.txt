================================================================================
2. STEP 1 — COPY FILES INTO YOUR PROJECT
================================================================================

  Simply copy the entire app/PaymentGateway/ directory and the two files:
    • app/Http/Controllers/Payment/UnifiedPaymentController.php
    • (optionally) app/PaymentGateway/config/payment-gateways.php

  If you prefer a different namespace prefix (e.g. "Modules\Payment"),
  perform a global search-and-replace:
    Find:    App\PaymentGateway
    Replace: Modules\Payment   (or your preferred namespace)


================================================================================
3. STEP 2 — REGISTER THE SERVICE PROVIDER
================================================================================

  Open  config/app.php  and add to the 'providers' array:

    App\PaymentGateway\Providers\PaymentGatewayServiceProvider::class,

  Optionally register the Facade in 'aliases':

    'Payment' => App\PaymentGateway\Facades\Payment::class,

  Laravel 11+: Add to bootstrap/providers.php instead:

    return [
        // ...
        App\PaymentGateway\Providers\PaymentGatewayServiceProvider::class,
    ];


================================================================================
4. STEP 3 — PUBLISH & EDIT THE CONFIG FILE
================================================================================

  Run:
    php artisan vendor:publish --tag=payment-gateways-config

  This copies  app/PaymentGateway/config/payment-gateways.php
  to           config/payment-gateways.php

  Then edit the 'gateways' section in config/payment-gateways.php and fill in
  your credentials (or use .env variables — recommended for production).

  To disable a gateway you don't need, remove its entry from 'drivers'.

6. STEP 5 — REGISTER PAYMENT ROUTES
================================================================================

  In  routes/web.php  add:

    require base_path('app/PaymentGateway/routes/payment.php');

  This registers:
    POST   /payment/{gateway}/charge    → UnifiedPaymentController@charge
    GET    /payment/{gateway}/success   → UnifiedPaymentController@success
    POST   /payment/{gateway}/success   → UnifiedPaymentController@success
    GET    /payment/{gateway}/cancel    → UnifiedPaymentController@cancel
    GET    /payment/confirmed           → payments.confirmed view
    GET    /payment/cancelled           → payments.cancelled view

  Create the terminal views:
    resources/views/payments/confirmed.blade.php
    resources/views/payments/cancelled.blade.php

  And the gateway-specific form views:
    resources/views/payments/razorpay.blade.php
    resources/views/payments/midtrans.blade.php
    resources/views/payments/paytm.blade.php
    resources/views/payments/iyzico.blade.php
    resources/views/payments/perfect-money.blade.php

7. STEP 6 — USAGE EXAMPLES
================================================================================

  ── 1. Simple redirect to checkout (e.g. PayPal, Mollie, Paystack) ───────────

    use App\PaymentGateway\DTOs\PaymentCharge;
    use App\PaymentGateway\PaymentManager;

    public function pay(Request $request, PaymentManager $payment)
    {
        $charge = PaymentCharge::fromArray([
            'amount'      => 99.00,
            'currency'    => 'USD',
            'description' => 'Premium Subscription',
            'success_url' => route('payment.success', 'paypal'),
            'cancel_url'  => route('payment.cancel',  'paypal'),
            'email'       => $request->user()->email,
            'order_id'    => 'ORDER-' . uniqid(),
        ]);

        $result = $payment->gateway('paypal')->charge($charge);

        if ($result->isRedirect()) {
            return redirect($result->redirectUrl, 303);
        }

        return back()->with('error', $result->errorMessage);
    }


  ── 2. Gateway selected by the user from a form ───────────────────────────────

    // Your form has: <select name="gateway"><option value="stripe">Stripe</option>...
    // POST to: /payment/{gateway}/charge  (the route handles it automatically)


  ── 3. Using the Facade ───────────────────────────────────────────────────────

    use App\PaymentGateway\Facades\Payment;

    $result = Payment::gateway('stripe')->charge($charge);


  ── 4. Synchronous gateways (Stripe, Authorize.Net) ──────────────────────────

    // These require a token from the JS library on the frontend.
    // Stripe example: include Stripe.js, generate stripeToken,
    // then POST stripeToken along with your form to /payment/stripe/charge.

    // Authorize.Net: include Accept.js, generate opaqueDataDescriptor +
    // opaqueDataValue, then POST them to /payment/authorize_net/charge.

8. STEP 7 — ADD YOUR POST-PAYMENT BUSINESS LOGIC
================================================================================

  After successful payment verification, UnifiedPaymentController@success
  has a clearly-marked placeholder block:

    // ──────────────────────────────────────────────────────────────
    // POST-PAYMENT LOGIC
    // Replace the block below with your own order fulfilment logic.
    // ──────────────────────────────────────────────────────────────

  Replace it with anything you need, for example:

    $order = Order::find($originalRequest['order_id']);
    $order->markAsPaid($transactionId, $gateway);
    Mail::to($originalRequest['email'])->send(new PaymentReceiptMail($order));
    return redirect()->route('dashboard')->with('success', 'Payment confirmed!');

  Alternatively, dispatch an event to keep the controller thin:

    event(new PaymentSucceeded($gateway, $transactionId, $originalRequest));

9. PER-GATEWAY COMPOSER PACKAGES & CONFIGURATION NOTES

────────────────────────────────────────────────────────────────────────────────
9.01  STRIPE
────────────────────────────────────────────────────────────────────────────────
  Package:
    composer require cartalyst/stripe-laravel

  Publish config:
    php artisan vendor:publish --provider="Cartalyst\Stripe\Laravel\StripeServiceProvider"

  Frontend requirement:
    • Include Stripe.js (https://js.stripe.com/v3/) in your checkout blade.
    • Use Stripe Elements or stripe.createToken() to generate stripeToken.
    • POST stripeToken to /payment/stripe/charge.

  Dashboard:
    https://dashboard.stripe.com/test/apikeys

  Credentials needed:
    STRIPE_KEY      (Publishable key — "pk_...")
    STRIPE_SECRET   (Secret key     — "sk_...")

────────────────────────────────────────────────────────────────────────────────
9.02  PAYPAL
────────────────────────────────────────────────────────────────────────────────
  Package:
    composer require paypal/rest-api-sdk-php

  Setup:
    1. Create a sandbox/live app at https://developer.paypal.com/developer/applications
    2. Copy the Client ID and Secret.

  Credentials needed:
    PAYPAL_CLIENT_ID
    PAYPAL_CLIENT_SECRET

  Note: The REST SDK uses PayPal's v1 API. For modern PayPal (Orders API v2)
        consider "srmklive/paypal" instead:
        composer require srmklive/paypal

────────────────────────────────────────────────────────────────────────────────
9.03  MOLLIE
────────────────────────────────────────────────────────────────────────────────
  Package:
    composer require mollie/laravel-mollie

  Publish config:
    php artisan vendor:publish --provider="Mollie\Laravel\MollieServiceProvider"

  Add to config/mollie.php (or it reads from config/payment-gateways.php via boot()):
    'key' => env('MOLLIE_KEY'),

  Dashboard:
    https://my.mollie.com/dashboard/developers/api-keys

  Credentials needed:
    MOLLIE_KEY   (test_...) for sandbox, (live_...) for live

  Note: Mollie does not use a sandbox flag — the key itself determines the mode.

9.15  PERFECT MONEY

      <script>document.getElementById('pmForm').submit();</script>

  Account:

  Credentials needed:

10. ADDING A CUSTOM GATEWAY
================================================================================

  1. Create  app/PaymentGateway/Gateways/MyCustomGateway.php:

     <?php
     namespace App\PaymentGateway\Gateways;

     use App\PaymentGateway\DTOs\PaymentCharge;
     use App\PaymentGateway\DTOs\PaymentResult;
     use Illuminate\Http\Request;

     class MyCustomGateway extends AbstractPaymentGateway
     {
         public function getKey(): string { return 'my_gateway'; }

         protected function boot(): void
         {
             $this->requireConfig(['api_key']);
         }

         public function charge(PaymentCharge $charge): PaymentResult
         {
             // ... call API, return PaymentResult::redirect($url) or failure
         }

         public function verify(Request $request): PaymentResult
         {
             // ... verify callback, return PaymentResult::success($txId) or failure
         }
     }

  2. Register it in config/payment-gateways.php:

     'drivers' => [
         // ... existing entries ...
         'my_gateway' => \App\PaymentGateway\Gateways\MyCustomGateway::class,
     ],

     'gateways' => [
         // ... existing entries ...
         'my_gateway' => [
             'api_key' => env('MY_GATEWAY_API_KEY'),
             'sandbox' => env('MY_GATEWAY_SANDBOX', true),
         ],
     ],

  3. Done — use it via:
     app(PaymentManager::class)->gateway('my_gateway')->charge($charge);

11. SECURITY CHECKLIST
================================================================================

  [ ] All credentials come from .env — never hard-code keys in source files.
  [ ] .env is in .gitignore and never committed to version control.
  [ ] Run in sandbox/test mode until you have tested every gateway flow.
  [ ] Validate and sanitize all user-supplied inputs before building PaymentCharge.
  [ ] Use HTTPS on all routes that handle payments.
  [ ] Verify callback signatures / hashes server-side (each gateway's verify()).
  [ ] Do not trust client-side amounts — always use the server-stored amount.
  [ ] Implement idempotency: check for duplicate transaction IDs before fulfilling.
  [ ] Enable CSRF protection (routes use 'web' middleware which includes VerifyCsrfToken).
      If a gateway POSTs to your callback, add the route to $except in VerifyCsrfToken.
  [ ] Rate-limit the /payment/{gateway}/charge route to prevent abuse.
  [ ] Log payment events (success, failure, refund) for audit trails.
  [ ] Use queue jobs for email notifications / order fulfilment to stay responsive.
